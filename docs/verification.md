화면 검사는 고정된 수업 이름·주소·슬라이드 개수를 사용하지 않는다. 차례와 장면 막대에서 검사 목록을 얻는다. 새 실습의 수업 고유 동작은 별도로 확인해야 한다. 재생 시계의 연속 동작과 저장 차단 시 동작은 동일한 공용 코드를 쓰는 Tailscale 차시에서 검증했으며, 여기서 다시 측정한 결과로 계산하지 않았다.

캡처·자동 검사 보고서는 `.local/captures/`에 남겼다. 저장 테스트의 예시 주소는 두 저장소 모두 `/activity/slide`로 정리했다. 정적 검사와 이미지 확인을 함께 사용했고, 예제 데이터가 바뀌어도 공용 UI를 수정하지 않는 분리 구조를 확인했다.

## 남은 제한

`npm audit --omit=dev`는 취약점 0건이다. 전체 audit에는 개발 의존성 5개에 high 경고가 있다. [picomatch 정규식 서비스 거부 취약점](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)이 원인이며 Vite와 빌드 플러그인까지 영향 경로로 표시된다. 자동 수정은 Vite 6.2.7과 React 플러그인 5.2.0으로의 주 버전 하향을 제안하므로 이번 복사에서는 적용하지 않았다. 개발 서버는 localhost에만 열고, 해당 도구들은 배포한 정적 사이트의 실행 의존성에 포함되지 않는다.

GitHub 원격 저장소 생성·공개·배포는 하지 않았다. GitHub Actions 설정은 포함했지만 원격 실행 결과는 아직 없다. 템플릿과 Tailscale 차시는 독립 저장소이며 이후 변경은 자동 동기화되지 않는다.
