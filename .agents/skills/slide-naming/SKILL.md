슬라이드 제목과 장면 이름은 학생이 **그 슬라이드를 보기 전에** 읽는다(차례, 재생 막대의 장면 칸, 「다음 장면: …」).
그래서 이름 하나만 읽고도 무엇을 하는지 말할 수 있어야 한다. 판단의 근거는 [slide-principles](../slide-principles/SKILL.md) 원리 2(한 뜻에 하나의 말)와 아래 출처다.
다른 스킬은 전용 호출 도구가 없어도 링크된 파일을 직접 읽는다. 코드 경로는 저장소 루트의 `src/` 기준이다.

## 규칙

1. **꼴은 「대상 + 하는 일」.** 무엇을(대상) 어떻게 하는지(하는 일)가 함께 드러나게 짓는다(「예측 몸무게 구하기」, 「뉴런 층 쌓기」, 「항등 함수로 쌓기」).
   - 개념 하나를 처음 소개하는 슬라이드는 그 개념 이름만 쓴다(「손실함수」, 「시그모이드 함수」, 「역전파」).
   - 앞에서 배운 것을 다시 짚는 복습 슬라이드는 다루는 주제의 이름으로 짓는다. 결론(「서버에서 비밀번호 확인」)이나 할 일을 제목에 담지 않는다(사용자, 2026-10-28: 제목이 「주제」였으면, 「보안」이 들어가게 → 「비밀번호 보안」).
   - 물음형(「~할까?」, 「~란?」, 「~면?」)으로 짓지 않는다. 물음은 자막과 낭독이 던지고, 이름은 그 슬라이드·장면이 하는 일을 말한다(「직선으로 나뉠까?」 → 「원 모양 데이터 나누기」). 퀴즈 장면은 「무엇 퀴즈 풀기」(「XOR 퀴즈 풀기」), 그래프의 축을 읽는 장면은 「무엇 읽기」(「손실 그래프 읽기」)로 짓는다.
   - 조작 장면(TRY)은 무엇을 바꾸는지 대상을 밝힌다(「활성화 바꿔 보기」 → 「항등 함수로 바꿔 보기」).
   - **슬라이드 제목(목차)은 명사로 끝낸다.** 하는 일을 「-기」가 아니라 명사(분류·비교·학습·시험 등)로 적는다(「두 무리 데이터 분류」, 「입력 특징과 은닉층 비교」, 「녹색 사과와 빨간 토마토 학습」). 「-기」(「구하기」, 「넣어 보기」)는 재생 막대의 장면 이름에만 쓴다(사용자, 2026-10-13). 이 규칙 전에 지은 「-기」 제목은 그 슬라이드를 고칠 때 함께 바꾼다(id 는 그대로, `title`만).
2. **이미 배운 말로 짓는다.** 그 슬라이드 안에서 처음 정의하는 말이나 비유(「켜진다」, 「띠」, 「휘기」)는 이름에 쓰지 않는다. 이름은 정의보다 먼저 읽히기 때문이다.
3. **앞 슬라이드의 낱말을 이어 받는다.** 차례가 이야기로 읽히게, 앞에서 쓴 말을 그대로 쓴다(「뉴런 층 쌓기」에서 정의한 「은닉 뉴런」 → 「두 은닉 뉴런으로 XOR 나누기」, 「원 모양 데이터 나누기」 → 「곡선 경계 만들기」).
4. **같은 꼴의 장면은 같은 꼴의 이름.** 하나씩 보이는 장면은 대상만 바꾼다(「OR 뉴런의 출력 칠하기」 · 「NAND 뉴런의 출력 칠하기」).
5. **핵심 낱말을 앞에, 짧게.** 재생 막대 칸에 들어가게 쓰고(`npm run capture`의 그림에서 잘리지 않는지 본다), 꾸밈말은 뺀다.
   - 차례의 제목은 한두 낱말로 줄일 수 있으면 줄인다(사용자, 2026-11-15: 「가입과 GitHub Desktop 설치 확인」 → 「배포 준비」, 「슬라이드 2는 조금 더 짧게 가능?」). 무엇을 준비하는지는 슬라이드의 첫 화면이 보여 준다.
   - 제목의 낱말은 받는 사람이 얻는 것 쪽에서 고른다. 수단보다 목적이다(같은 날: 「슬라이드 6의 제목은 저장보다도 '공유'에 초점 두면 어떨까?」 → 「저장이 필요한 웹앱」 → 「자료를 공유하는 웹앱」).
   - 활동의 첫머리에는 그 활동이 끝나면 할 수 있는 일을 적은 「연수 목표」 · 「수업 목표」 슬라이드를 둘 수 있다(같은 날: 「배포」 → 「연수 목표」, 「github에 코드를 올리고 웹앱의 용도에 따라 배포할 수 있다」).

## 쓰지 않는 꼴

| 꼴                                         | 왜 안 되나                                   | 고친 예                                                                                                   |
| ------------------------------------------ | -------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 조건·생략(「~라면」, 「~없이」, 「~보면」) | 무엇을 하는지 말하지 않는다                  | 「활성화 없이」·「항등 함수라면」 → 「항등 함수로 쌓기」, 「한 축에서 보면」 → 「시그모이드로 값 모으기」 |
| 대상 없는 동작                             | 무엇이 그 일을 하는지 모른다                 | 「켜지는 곳 겹치기」 → 「두 은닉 뉴런으로 XOR 나누기」                                                    |
| 안에서 정의하는 말·비유                    | 보기 전에는 뜻을 모른다                      | 「켜지는 곳」, 「공간 휘기」                                                                              |
| 물음형(「~할까?」, 「~란?」, 「~면?」)     | 촌스럽고, 하는 일 대신 물음만 남는다(사용자) | 「직선으로 나뉠까?」 → 「원 모양 데이터 나누기」, 「학습이 부족할까?」 → 「손실 그래프 읽기」             |
| 상태 서술(「~하게 ~된다」)                 | 결과를 먼저 말해 장면이 하는 일이 없다       | 「둘 다 켜진 곳」 → 「AND 뉴런으로 겹치기」                                                               |

## 이름을 바꿀 때

- 활동·슬라이드 제목은 `title`, 장면 이름은 `label`이다. `id`는 주소·이어보기 기준이므로 유지한다. 폴더를 옮겨도 ID와 순서는 바꾸지 않는다.
- 장면 이름은 저장 키가 아니다. 이 템플릿의 낭독 원고도 활동/슬라이드/장면 ID로 가리킨다. 장면의 의미나 자막을 바꾸면 원고를 함께 확인한다.
- 퀴즈 ID는 수업 안에서 유일해야 한다. 문제·선택지 의미를 바꾸면 `Quiz`의 `revision`을 올려 이전 답과 구분한다.
- 옛 이름을 가리키는 자막·설명·주석을 `rg -n -F '옛 이름' src/lesson`으로 찾아 함께 고친다.

## 출처

- 제목은 따로 떨어져 읽혀도 뜻이 서야 하고, 핵심 낱말을 앞에 두며, 말장난·전문어를 피한다([NN/g, Headings Are Pick-Up Lines](https://www.nngroup.com/articles/headings-pickup-lines/)).
- 차례와 맞물린 제목은 내용의 짜임을 알려 주어 불필요한 처리를 줄인다(신호 주기 원리, signaling: [Mayer & Fiorella](https://www.cambridge.org/core/books/abs/cambridge-handbook-of-multimedia-learning/principles-for-reducing-extraneous-processing-in-multimedia-learning/F29A19FCD34C542806F736E0661C05F5)).
