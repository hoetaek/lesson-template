화면 검사는 고정된 수업 이름·주소·슬라이드 개수를 사용하지 않는다. 차례와 장면 막대에서 검사 목록을 얻는다. 새 실습의 수업 고유 동작은 별도로 확인해야 한다. 정지 화면 검사만으로 재생 중간 움직임이 모두 검증됐다고 판단하지 않는다.

캡처·자동 검사 보고서는 `.local/captures/`에 남겼다. 저장 테스트는 특정 수업 이름에 의존하지 않는다. 정적 검사와 이미지 확인을 함께 사용했고, 예제 데이터가 바뀌어도 공용 UI를 수정하지 않는 분리 구조를 확인했다.

## 남은 제한

`npm audit --omit=dev`는 취약점 0건이다. 전체 audit에는 개발 의존성 5개에 high 경고가 있다. [picomatch 정규식 서비스 거부 취약점](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)이 원인이며 Vite와 빌드 플러그인까지 영향 경로로 표시된다. 자동 수정은 Vite 6.2.7과 React 플러그인 5.2.0으로의 주 버전 하향을 제안하므로 이번 복사에서는 적용하지 않았다. 개발 서버는 localhost에만 열고, 해당 도구들은 배포한 정적 사이트의 실행 의존성에 포함되지 않는다.

GitHub 원격 저장소 생성·공개·배포는 하지 않았다. GitHub Actions 설정은 포함했지만 원격 실행 결과는 아직 없다. 복사해 만든 차시와 이후 변경은 자동 동기화되지 않는다.

## 구조·스킬·독립 실행 확인

활동별 `index.ts`와 슬라이드별 `slide.tsx`로 파일을 나누고 전용 그림·실습을 해당 폴더에 옮겼다. 분리 전후 슬라이드 객체를 정규화해 비교했으며 내용이 같았다. 브라우저에서 수집한 슬라이드·장면 주소와 순서도 같았다. 변경 후 전체 화면·기능 검사를 통과했다.

실제 차시를 불러 검사하는 `check:content`를 검사·빌드에 연결했고, 공용 재생기·부품·규칙이 수업 내용을 가져오지 않는지 테스트한다. 제작·수정·표현·제목·낭독 원고 다섯 스킬은 형식 검사와 상대 링크 검사를 통과했다. 스킬 적용 실행안도 실제 타입·상태 저장·명령과 대조했다. 음성 생성은 지원 범위에 포함하지 않는다.

사이드바와 모바일 상단의 처음 이동 화살표를 제거하고 제목에 8px 왼쪽 여백을 주었다. 처음 이동은 상단 차시 제목으로 확인했다. 차례 항목과 제목의 시작선 일치, 접기·펼치기·Escape 닫기를 확인했고 독립 검토도 통과했다. 전체 페이지 캡처에 화면이 반복된 경우 새 페이지의 viewport 캡처와 단일 앱·헤더 DOM을 대조해 촬영 문제임을 구분했다. 관련 이미지는 `.local/sidebar-cleanup/`에 있다.

프로젝트를 별도 임시 폴더에 복사해 `npm ci`, `npm run check`, `npm run build`를 통과했다. `.claude/skills/`의 다섯 상대 링크는 복사본 내부에서 해결됐다. 소스·문서·스킬에 외부 로컬 프로젝트의 이름이나 절대 경로가 남지 않음을 확인했다. 파일을 폴더로 옮긴 뒤 개발 서버가 이전 파일 경로를 캐시한 경우 서버를 재시작해 해결했고 최종 브라우저 검사를 통과했다.
